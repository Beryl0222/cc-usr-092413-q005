# 银发服务体验认证

服务用于记录不同银发人群的真实体验证据、适用范围和认证变更，避免笼统宣传掩盖差异。

当前版本提供**认证范围拆分与承接**能力：原认证覆盖的旅居服务拆分为两个运营主体
（一家保留场地与员工，另一家接手线上签约与健康支持）时，系统不允许整张证书直接
转移，而是要求重新证明新的责任边界。

项目提供稳定的基础服务入口，便于本地联调和运维巡检。运行 `python3 service.py --check`
可核对服务配置；执行 `python3 service.py --port 8000` 后访问 `/health` 可确认服务身份。

## 拆分承接流程

1. **登记原证书与证据**：服务组件、人群分层、地点、责任方、有效期，以及标注了适用
   范围（组件/人群/地点）的体验证据；无法分割的严重事件、共用人员、共享设施单独登记。
2. **冻结原证书**：`POST /splits/freeze` 固化组件、人群、地点、责任方与有效期快照；
   未冻结不得发起拆分，冻结操作幂等。
3. **发起拆分与分别声明**：两个新主体分别提交承接项、控制措施、缺口，以及责任承接与
   投诉承接意愿。
4. **可继承候选**：`POST /splits/candidates` 依据证据适用范围给出候选；证据标注为范围
   之外、人群/地点不匹配或仅部分适用时，逐条记录未继承原因。
5. **双轨确认**：评审员确认体验覆盖（experience），合规人员确认责任与投诉承接
   （compliance）；未声明责任或投诉承接的，合规不得通过。
6. **签发独立新版本**：`POST /splits/issue` 为两个主体生成互不相同的新认证版本。
   - 无法分割的严重事件、共用人员、共享设施只令**相关组件**暂停，不波及其余组件；
   - 同一组件被两个主体同时承接会被拒绝，责任边界必须唯一；
   - 证据部分缺失或存在自认缺口时为部分通过，范围收窄；评审驳回的范围不予签发。
7. **幂等与复审**：相同承接方案重放不重复签发；某主体声明内容变化后其评审结论失效，
   重新确认后只为该主体生成新版本，旧版本标记为 `superseded` 并留痕，不影响另一主体。
8. **追加事实**：整改（可解决暂停所依赖的事件）、组件级/整证撤销均以追加事实保存，
   已有事实不被改写。
9. **宣传引用**：拆分期间新引用必须指向当前明确版本；冻结、暂停、撤销、被取代的版本
   均不可引用。
10. **已购用户处置**：原承诺保留；承接生效时记录责任变更并通知，范围暂停时承诺保留、
    等待整改，整改恢复后补发责任转移记录。
11. **追溯**：`GET /trace/{新证书ID}` 可回到原证书冻结快照、原证据、未继承原因、
    评审结论、追加事实与历史消费者处置。

> 当前实现为单进程内存存储，重启后数据清空，适用于联调与合同验证；事实模型可直接
> 落到持久化事件库。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务身份健康检查 |
| POST | `/certificates` | 登记原证书 |
| GET | `/certificates` | 列出证书（公开视图） |
| GET | `/certificates/{id}` | 查看单张证书（含追加事实） |
| POST | `/evidence` | 登记体验证据及适用范围 |
| POST | `/events` | 登记严重事件/共用人员/共享设施 |
| POST | `/consumers` | 登记已购用户 |
| POST | `/splits/freeze` | 冻结原证书 |
| POST | `/splits` | 发起拆分（两个承接主体） |
| GET | `/splits/{id}` | 查看拆分流程状态 |
| POST | `/splits/declarations` | 提交/修订承接声明 |
| POST | `/splits/candidates` | 生成证据可继承候选 |
| POST | `/reviews/confirm` | 体验覆盖 / 责任与投诉承接确认 |
| POST | `/splits/issue` | 签发独立新版本（幂等） |
| POST | `/certificates/remediation` | 提交整改（追加事实，可解决事件） |
| POST | `/certificates/revoke` | 撤销整证或单个组件（追加事实） |
| POST | `/citations` | 登记宣传引用（须指向当前明确版本） |
| GET | `/trace/{id}` | 从新证书追溯原证据、未继承原因与消费者处置 |

领域规则冲突返回 `422` 与错误原因；请求体非法 JSON 返回 `400`；未知路由返回 `404`。

## 代码结构

- `certification.py`：拆分承接领域服务（冻结、声明、候选、双轨评审、签发、暂停隔离、
  幂等/复审、追加事实、引用校验、消费者处置与追溯）。
- `service.py`：HTTP 入口与路由，`create_handler_class()` 可绑定独立服务实例。
- `domain_contract.py`：领域规则合同测试（25 例）。
- `service_contract.py`：健康检查与端到端 HTTP 流程合同测试（6 例）。

## 测试与构建

执行完整测试：

```bash
npm test
```

执行编译检查：

```bash
python3 -m compileall -q .
```

两条命令都可在单个 Linux 应用容器内直接运行，不需要额外服务。
